# Optional independent validation service

## What is ready, and what still needs hosting

`server.cjs` is a complete Node HTTP service, with no production npm dependencies. **It is not deployed.** GitHub Pages cannot execute server code. Uploading the website ZIP alone provides the working static calculator and WhatsApp journey, not server validation.

Use a Node-capable HTTPS hosting service of your choice. There is no account, secret or hosting subscription configured in these files.

## Deploy

1. Deploy the same repository files, including root JS/configuration and generated `en/` modules, to your Node host.
2. Use Node.js 24 (or a compatible modern Node runtime).
3. Set these environment variables in the host's secret/settings interface:
   - `QUOTE_SECRET`: a new random secret of at least 32 characters. Generate one locally with `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Never commit it or put it in browser JavaScript.
   - `PUBLIC_URL`: the HTTPS base URL of this service, without `/quote`.
   - `ALLOWED_ORIGIN`: `https://warshabeteya.github.io` (an origin has no repository path).
   - `PORT`: use the hosting provider's port setting; defaults to `8787`.
   - `TRUST_PROXY`: leave unset unless your host is behind a trusted proxy that overwrites `X-Forwarded-For`. Set `1` only after confirming that configuration. Otherwise rate limits use the socket address.
4. Start with `node server/server.cjs` or `npm run start:validation`.
5. Open `/health`; it should return `{"ok":true}`.
6. In the website's `site-config.js`, set `validationEndpoint` to the full HTTPS `/quote` URL. Upload that file to GitHub Pages. No rebuild is needed because both languages load this shared configuration.
7. Complete an Arabic and English request. Check the signed verification link in the prepared message. No request is sent to the workshop until the visitor sends it on WhatsApp.

To disconnect the service, set `validationEndpoint:''` and upload `site-config.js` again.

## Validation and trust boundary

The server validates required fields, Egyptian mobile formatting, text types/limits, device/service compatibility, duplicate extras, Linux choices and backup confirmation, explicit modification choice and required consent. It recomputes prices and active promotions from the server catalogue and Cairo date. Client-supplied prices, discounts and references are ignored.

A signed, 24-hour verification link proves the displayed estimate was generated by this server. The link contains selected services and amounts, **not the customer's name, phone or free-text notes**. It does not prove identity, phone ownership, device condition, service compatibility or payment. It is not a booking confirmation or guaranteed quote. Confirm the actual work on WhatsApp.

The service keeps no order database and does not log request bodies. Your hosting provider may keep network/access logs. A temporary in-memory per-IP limiter allows 30 quote requests per minute. This is suitable for a small single-instance deployment; use a shared rate limiter at the hosting edge before scaling to multiple instances. It resets on restart.

JSON POST requests are limited to 32 KiB. CORS is restricted to the configured origin. No secret is exposed to the browser. If the server catalogue differs from the browser and produces a different total, the visitor is asked to refresh and review rather than silently accepting a changed price.

## Keeping prices and promotions synchronized

After changes to `data.js`, root logic or translations, run `npm run build` and `npm test`; deploy the website and server together. For campaign/config changes, update the same `campaigns.js` and `site-config.js` on both hosts and restart the Node service. Do not serve stale server prices against a new website release.
